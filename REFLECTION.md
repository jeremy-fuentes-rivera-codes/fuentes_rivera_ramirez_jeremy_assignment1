## Code Review Process
### 1. Can I explain what my code does?
My code is organized semantically to mimic the structure of a standard resume and follow high accesibility standards. While integrating the required SVG graphics altered the layout slightly from a traditional resume, the overall visual presentation remains professional. 
The primary reason why I used semantic HTML elements and ARIA standards in my html is to maximize accessibility and comply with web design standards. I structured sections "Experience" and "Education" using <div> containers so that the dates were cleanly aligned to the right via CSS flexbox layout properties. Rather than wrapping navigation links inside nested <ul> and <li> structures, I used <p> elements within <nav> structures. This change was mainly done because of the concern that semantics could be affected negatively if <div> was placed before them.On the styling side, the CSS and HTML work together to ensure responsiveness and good visuals. I used Flexbox properties like  "flex-wrap" to create a circular profile photo and better display the links below my name. Using CSS media queries helped me make my website more readable across different screen sizes without forcing the user to scroll horizontally.

### 2. What was my coding process?
My process began with planning. First, I sketched a quick initial paper layout and then built a visual mockup in Figma. This allowed me to visualize the final structure before writing any code. Because the assignment objective was to build a resume on a website, I kept the layout very similar to a standard resume, adding only a profile photograph and interactive header links to adapt it for the web.

### 3. What challenges did I have?
I faced initial challenges working with Git in the terminal. Specifically, this happened when I executed the last commands of the assignment. I resolved these issues by verifying my current working directory path and consulting git documentation. On the HTML side, I struggled with applying semantic tags correctly. For example, I wanted to ensure that <div> elements were implemented without violating semantic rules. For this, I watched the instructor’s past class demonstrations and documentation. I ended up applying <div> with <p>.
Finally, ensuring smooth responsiveness presented a challenge. Figuring out how content should scale when zooming in or out and preventing horizontal scrolling across different devices. I resolved this by revisiting class notes and demo recordings, I utilized the "flex-wrap" property, and adjusted font sizes using media queries. Finally, I tested the site with axe DevTools confirmed the layout met standards with zero accessibility errors.


### 4. What would I do differently now?
If I were starting this project over, I would approach the structural layout with greater confidence, knowing that div goes along with p, so it doesn't violate semantics. I would also apply the flex-wrap` and adjusted font sizes from the beginning. Overall, overcoming these initial obstacles has given me a clearer understanding of semantic HTML structure, CSS layout tools, and accessibility standards that I can apply directly to future projects.
